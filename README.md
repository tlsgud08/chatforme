# Inuchat — AI 롤플레잉 채팅 플랫폼

개인/지인용 AI 롤플레잉 채팅 플랫폼. OpenRouter API 키 하나를 입력해 사용하는 **BYOK** 방식이라 운영 비용이 거의 들지 않습니다.

- **프론트엔드**: Vite + React + TypeScript + Tailwind (모바일 우선 PWA)
- **백엔드**: Supabase (Auth · Postgres · Storage) — 무료 티어
- **AI 호출**: 브라우저에서 OpenRouter로 직접 호출 (키는 서버에 저장되지 않음)

---

## 화면 디자인

설정의 **화면 디자인 → 개선형 / 레거시**에서 이 기기의 화면 구성을 선택합니다.
개선형은 데스크톱에서 좌측 탐색과 넓은 본문, 가로 태블릿에서 간결한 탐색을 사용합니다.
채팅 본문은 읽기 좋은 폭을 유지하며, 작품 목록과 편집 화면은 화면 너비에 맞춰 배치됩니다.
레거시는 기존 480px 폭과 하단 탭으로 돌아갑니다. 새로고침 후에도 선택이 유지됩니다.
색상 테마(라이트·다크·커스텀), 작품별 자동 테마와 낮·밤 규칙은 이 선택과 독립적입니다.
세션 메뉴는 두 디자인 모두 기존 우측 측면 메뉴와 항목 순서를 그대로 사용합니다.
DB 마이그레이션은 필요하지 않습니다.

## 핵심 개념

- **작품(Work)**: 제목·설명·썸네일 + 메인 프롬프트 + 키워드북. 시스템 프롬프트는 전역 공통(관리자 설정).
- **세션(채팅방)**: 작품을 실제로 플레이하는 공간. 세션마다 독립된 대화 기억·유저 노트·출력량 설정.
- **유저 노트**: 세션별 글자 수 제한 없는 메모. 측면 메뉴에서 언제든 편집하며, 프롬프트의 독립된 `User Notes` 영역에 주입됨.

## 처음 실행하기 (5단계)

### 1. 패키지 설치
```bash
npm install
```

### 2. Supabase 프로젝트 만들기
1. https://supabase.com 에서 무료 프로젝트 생성
2. **SQL Editor**에서 `supabase/migrations/0001_init.sql` 내용을 붙여넣고 실행 (테이블·보안 정책 생성)
3. **Storage**에서 `thumbnails` 라는 이름의 **public 버킷** 생성
4. **Authentication → Providers**에서 Google 로그인을 쓰려면 Google OAuth 설정 (이메일 로그인은 기본 활성화)

### 3. 환경변수 설정
`.env.example`을 복사해 `.env` 를 만들고 값을 채웁니다.
```bash
cp .env.example .env
```
```
VITE_SUPABASE_URL=https://xxxx.supabase.co       # Project Settings → API
VITE_SUPABASE_ANON_KEY=eyJhbGci...                # Project Settings → API (anon public)
VITE_ADMIN_EMAIL=your@email.com                   # 본인(관리자) 이메일
```

### 4. 개발 서버 실행
```bash
npm run dev
```
브라우저에서 안내되는 주소(기본 http://localhost:5173)로 접속.

### 5. 앱 안에서 API 키 입력
로그인 후 **설정 탭 → API 키**에 키를 입력하면 채팅이 동작합니다.
(키는 이 기기 브라우저에만 저장됩니다.)

> **OpenRouter API 전용**
> [openrouter.ai](https://openrouter.ai) 에서 키 하나를 발급하면 Claude·Gemini·GPT 등 모든 모델을 단일 키로 사용할 수 있습니다.
> 무료 모델도 제공되므로 처음 사용하기에 가장 편리합니다.

- 과거 특정 턴을 기준으로 요약을 생성해도 같은 규칙을 적용한다.

## 명시적 캐시 (OpenRouter)

- 배포 전 `supabase/migrations/0036_manual_prompt_cache.sql`을 적용한다. 기존 채팅방은 기본 OFF이며, 기존 세션 RLS가 설정 저장에도 적용된다.
- 채팅방 사이드 메뉴의 요약 메모리 설정 바로 아래에서 ON/OFF 및 기준 턴을 저장한다. OFF 요청에는 `cache_control` 필드를 전혀 보내지 않는다. 제공업체의 자동 캐시를 끄는 기능은 아니다.
- 시스템 프롬프트까지만 또는 특정 완료 AI 답변까지 지정할 수 있다. 시스템에는 작품 설정, 페르소나, 유저 노트, 요약, 스토리 노트가 포함된다.
- 수동 모드에서는 선택한 답변 ID를 고정하며 새 턴이 생겨도 경계를 이동하지 않는다. 요약·삭제·리롤로 대상이 실제 전송 문맥에서 빠지면 안내 후 해당 요청에서 명시적 경계를 생략한다. 분기 채팅방은 새 ID를 사용하므로 기본 OFF로 시작한다.
- 모든 모델에서 설정을 사용할 수 있으며 콘텐츠 블록의 `cache_control: { type: "ephemeral" }`을 전송한다. 게스트 채팅, 요약 생성에는 적용하지 않는다. 실제 지원 여부와 최소 토큰 수는 OpenRouter 제공 경로에 달려 있다.
- 명시적 모드에서 활성 키워드북은 현재 사용자 입력 앞에 붙인다. 캐시된 Gemini 시스템 지시문에 매 턴 바뀌는 키워드가 섞이지 않도록 하기 위함이다. OFF일 때는 기존 메시지 배치를 유지한다.
- 캐시 지정은 적중 보장이 아니다. 만료나 내용/경계 변경으로 새 쓰기 비용이 발생할 수 있다. 기존 캐시 읽기·쓰기 토큰 표시와 OpenRouter 사용 내역으로 실제 적용을 확인한다.
- `npm test`는 OFF 요청 형식, 경계 고정, 요약/삭제/리롤 대상 검증, 메시지 정규화 및 실제 어댑터의 HTTP 본문을 검증한다(외부 API는 모의 응답).

### 채팅방 플러그인

- 배포 전에 `supabase/migrations/0037_session_plugins.sql`을 Supabase SQL Editor에서 실행한다. 개인/공개 플러그인, 사용자별 즐겨찾기, 세션 활성화 목록을 추가하며 RLS로 소유자만 수정할 수 있다.
- 채팅방 측면 메뉴의 유저 노트 바로 아래에서 플러그인을 추가하고 비활성화한다. 추가 메뉴는 전체/내 플러그인/허브/즐겨찾기와 이름·설명·작성자 검색, 생성·편집·삭제·공개·복사를 제공한다.
- 활성화 시 이름·설명·본문을 채팅방에 복사하여 저장한다. 원본 수정·비공개·삭제가 기존 채팅방의 지시를 변경하지 않는다. 갱신하려면 비활성화 후 다시 추가한다. 개수 제한 없이 복수 활성화할 수 있다. 활성화 순서로 매 일반 채팅 요청(재생성 포함)의 시스템 프롬프트 `session prompts` 영역에 전송한다. 명령어 선택 없이도 유지되며 요약 생성에는 주입하지 않는다.
- 채팅방 재접속 시 유지되고 분기 채팅방에도 복사된다. 비활성화하면 다음 요청부터 본문을 제외한다. 수동 캐시 0에도 포함되므로 플러그인 변경 시 기존 캐시 재사용이 달라질 수 있다.
- 페르소나는 드롭다운에서 선택하고 현재 선택한 페르소나 설명만 표시한다.

### 캐시 기준 자동 갱신

- `supabase/migrations/0038_auto_latest_prompt_cache.sql`을 적용한다. 기존 채팅방은 자동 갱신 OFF로 시작한다.
- 명시적 캐시 설정에서 매 턴 최신으로 갱신을 켜면 실제 전송 문맥의 마지막 완료·활성·표시 AI 답변에 경계를 둔다. 요약/삭제/리롤 후에도 요청마다 다시 해석하며, 대상이 없으면 시스템 프롬프트만 지정한다. 현재 사용자 입력과 생성 중/중단된 답변은 포함하지 않는다.
- ON일 때 숫자 입력은 현재 최신 선택 가능 턴을 표시하며 직접 변경할 수 없다. OFF로 되돌리면 보존한 수동 기준을 사용한다. 채팅방별 설정으로 저장된다.
- 명시적 캐시 자체가 OFF이면 자동 갱신 설정과 관계없이 cache_control을 전혀 전송하지 않는다.


## 테마 허브 · 작품 전용 테마/명령어

**배포 순서:** Supabase에 `supabase/migrations/0039_work_themes_and_commands.sql` 적용 후 **`supabase/migrations/0040_theme_command_integrity.sql`까지 순서대로 실행**하고 프론트엔드를 배포합니다. 0039을 이미 적용했다면 **0040만 새로 실행**하세요. 0038까지 적용되어 있어야 합니다. 기존 `dark` / `light` 색 정의는 보존됩니다.

- 작품 탭에서 `작품 / 명령어 / 플러그인 / 테마`를 전환할 수 있습니다. 테마와 명령어는 `전체 / 작품 / 내 항목 / 허브 / 즐겨찾기`를 제공합니다. 허브 항목을 복사하면 독립적인 개인 항목으로 저장됩니다.
- 테마 제작자는 다크/라이트 지원 버전을 체크박스로 직접 지정합니다. 버전마다 강조색, 강조색 글자, 메인색, 메인색 글자 네 색상을 **각각 수동 지정**합니다. 미지원 버전을 자동 생성하지 않습니다. 메인색으로부터 표면색 두 단계만 파생합니다.
- 작품 편집기의 기본정보에서 **작품 기본 테마**를 선택하고 작품 전용 테마를 제작할 수 있습니다. 작품 전용 테마는 해당 작품의 채팅방에서만 선택 가능합니다. 일반 글로벌 테마를 작품 기본값으로 지정하려면 허브 공개 상태여야 합니다.
- 작품 편집기의 `키워드북 · 명령어` 탭에서 작품 전용 명령어를 여러 개 제작합니다. 기존 키워드북의 자동 주입과 명령어의 사용자가 선택하는 프롬프트는 별도 동작합니다. 작품 명령어는 다른 작품에서 선택할 수 없고, 허브 공개 및 개인 복사가 제한됩니다.
- 설정에서는 개인 기본 다크/라이트/커스텀 테마 및 `작품 테마 기본 사용` 여부를 저장합니다. 로그인 계정 설정, 테마, 작품 기본값, 채팅방 개별 선택은 모두 Supabase에 저장됩니다. 브라우저 포커스/경로 변경 시 재동기화합니다.
- **우선순위:** 채팅방 직접 선택 > 작품 기본 테마(개인 설정에서 허용 시) > 사용자 기본 테마. 채팅방은 기본값 상속, 기본 다크/라이트 강제, 커스텀 테마 중 하나를 선택합니다. 커스텀 테마가 두 버전을 모두 제공하는 경우에만 버전 토글이 나타납니다.
- 작품 복제 시 작품 전용 테마/명령어를 복사하고, 기본 테마를 원본 UUID로 추적해 올바른 복사본을 가리키도록 변경합니다.
- 0040은 각 작품별 명령어 이름의 유일성, 전용 콘텐츠의 소속 불변성, 색상 HEX 데이터 검증, 테마 삭제 시 채팅방 기본값 복구를 보장합니다.
- 브랜치/채팅방 분기 시 채팅방의 독립 테마 선택도 복사됩니다. 추후 AI의 자동 테마 전환은 **이 변경에 포함되지 않습니다.**

기존 `inuchat.theme` 로컬 저장값은 로그인 전 및 개인 기본 모드를 아직 정하지 않은 기존 계정의 초기 표시로 유지합니다. 개인 기본 모드를 한 번 지정하면 DB 설정이 우선합니다. 로그인 이후의 모든 테마 설정은 계정 기준으로 동기화됩니다.

### 점검 체크리스트

### 자동 작품 테마 변경

`supabase/migrations/20261014031245_automatic_work_themes.sql`을 0040 이후 적용해야 합니다. 기존 작품 테마는 공용으로 유지되고, 자동 변경은 기본적으로 꺼져 있습니다.

- 운영자 설정의 전역 시스템 프롬프트 아래에서 테마 판단 전역 프롬프트를 편집합니다. 작품 메인 프롬프트 → 테마 판단 규칙 → 작품 테마 이름/AI 적용 조건 순서로 시스템 core에 배치됩니다.
- 채팅방 테마 메뉴는 기본값 / 작품테마 / 기본 테마 / 커스텀입니다. 작품테마에서 누구나 자신만 사용하는 작품 전용 테마와 AI 적용 조건을 만들 수 있습니다. 공용 테마는 작품 제작자/편집자가 관리합니다.
- 자동 변경 ON: AI가 응답 마지막에 `{{theme::이름}}` 또는 `{{theme::keep}}`을 출력합니다. 과거 태그도 대화 이력에 유지됩니다. OFF: 테마 지침/목록/현재 테마 정보를 제외하고, 대화 및 요약 전송본에서 태그를 제거합니다. 저장 원문은 유지합니다.
- 태그는 일반 화면과 스트리밍에서 숨기고 편집에서는 표시합니다. 마지막 활성 AI 응답의 태그 변경, 새 응답, 리롤 선택은 테마를 적용합니다. `keep`, 없는 이름, 중복 이름은 아무 동작을 하지 않습니다. 이전 응답 편집은 현재 테마를 바꾸지 않습니다.
- 수동 선택은 다음 유효한 태그 변경까지 유지됩니다. 기본값은 개별 선택을 해제하고 작품/개인 기본 설정을 따릅니다. 새로고침이나 자동 변경 ON 전환은 기존 태그를 재실행하지 않습니다.
- 변경 색상은 0.4초 동안 전환하며 기기의 동작 줄이기 설정을 따릅니다.

`npm test`는 태그 스트리밍/페이로드/변경 감지와 PGlite Postgres의 마이그레이션 및 RLS 허용/차단 동작을 검증합니다. 운영 DB 마이그레이션 적용이나 실제 LLM 호출은 수행하지 않습니다.

### 보조 텍스트 색상

테마의 다크/라이트 버전마다 `secondaryText` HEX 색상과 `softenSecondaryText` 토글과 `secondaryTextOpacity` 불투명도(0~100)를 설정할 수 있습니다. 토글 기본값은 ON이며, 채팅의 `*텍스트*`와 코드 블록 안의 같은 문법은 기본 65% 불투명도로 표시되며 슬라이더로 조절할 수 있습니다. OFF이면 선택한 색을 그대로 표시합니다. 사이트의 기존 보조 텍스트 색상 클래스와 테마 미리보기에도 적용됩니다.

두 필드는 선택 사항이므로 기존 4색 테마는 기존 채팅 글자색을 사용하며 불투명도 기본값은 65%입니다. 저장 전에 `supabase/migrations/20261014034744_theme_secondary_text.sql`과 `supabase/migrations/20261014044407_theme_secondary_opacity.sql`을 순서대로 실행하여 DB 팔레트 검증을 확장해야 합니다. 기본 다크/라이트로 돌아가면 추가 CSS 변수는 초기화됩니다.

- `supabase/migrations/20261027145952_multichat_shared_experience.sql`을 적용합니다. 기존 멀티챗 기록과 ID를 보존하면서 일반 세션의 설정·프롬프트·메모리 경로에 연결합니다.

- 모든 로그인 사용자의 멀티챗 목록에 방이 즉시 표시되며 시작 전/진행 중으로 구분합니다. 초대 코드나 비밀번호 입력 없이 빈자리에 참가합니다. 전체 목록 공개는 대화 본문이나 API 키 공개를 뜻하지 않습니다.
- 일반 채팅의 `MessageContent`, `SessionMenu`, 테마·작품 결합·플러그인·출력/캐시 설정을 함께 사용합니다. PC별 페르소나와 유저 노트는 독립적으로 저장하며 두 입력을 `페르소나명(PC1): ...\n\n페르소나명(PC2): ...`로 묶어 일반 OpenRouter `user` 메시지에 전송합니다.
- 전송한 행동은 DB 응답을 기다리기 전 말풍선에 표시하며, 확인되지 않은 입력으로는 AI 호출을 시작하지 않습니다. 별도 유저 대화 버튼은 같은 입력창의 내용을 즉시 점선 말풍선으로 보내며 AI 문맥·요약에서 제외합니다.
- API 사용 규칙은 방장과 참여자 모두 바꿀 수 있습니다. PC1만/PC2만/PC별 1~1,000개의 연속 턴 수로 교대를 제공하며 시작할 PC도 지정합니다. 규칙을 변경한 시점부터 새 주기를 시작하고 이미 호출 중인 응답은 원래 담당자가 완료합니다. 호출 담당자의 브라우저에만 키가 필요하며, 그 브라우저가 방을 열고 있어야 합니다.
- 두 참여자 모두 자신·상대의 입력, AI 응답, 유저 간 대화를 수정·삭제할 수 있습니다. 다른 참여자가 편집 중인 메시지 아래에는 수정 중 표시가 나타나며, 편집 내용 자체는 공유하지 않습니다. 동시 변경은 원문 검사로 충돌을 알립니다. 대화 생성·요약 중에는 유저 간 대화만 수정·삭제할 수 있습니다.
- 삭제한 내용은 일반 세션의 AI 문맥에서도 제거하고 영향을 받는 요약을 무효화합니다. 리롤 답변 하나를 삭제하면 남은 완료 답변을 선택하며, 사용한 API 비용은 유지합니다. 리롤·답변 선택은 방장만 가능하고 분기는 UI와 DB 모두 차단합니다.
- 채팅 본문에는 AI 이름표와 PC 번호를 표시하지 않습니다. PC1/PC2는 입력 페이로드의 내부 식별자이며, 프롬프트의 `{{pc1}}`·`{{pc2}}`·`{{user1}}`·`{{user2}}` 참조는 페르소나 이름으로 해석합니다. 서술·대사에는 실제 인물 이름을 사용하며 이미지 URL·코드 안의 문자열은 보존합니다.
- 요약/요약 병합은 어느 참여자든 요청할 수 있고 현재 API 규칙 담당자가 생성합니다. 공용 요약과 작품 결합·테마·키워드북·스토리 노트·명령어·플러그인·명시적 캐시는 기존 조립기를 사용합니다. 저장이 확인되지 않은 응답과 요약은 계정별로 보관해 API 재호출 없이 저장을 재시도합니다.
- 생성 ID와 claim token으로 중복 호출·오래된 완료·비용 중복 집계를 막습니다. 8분이 지나 중단된 생성은 명시적으로 재시도할 수 있습니다. 실시간 스트리밍은 변경 행만 갱신하여 전체 기록을 반복 조회하지 않습니다.
- `node scripts/test-multichat-shared.mjs`는 실제 전체 DB 마이그레이션/RLS, 지정 턴 수/단일 키, 호출 중 규칙 변경, 리롤 요청/실행 분리, 메모리, 일반 프롬프트 조립→HTTP 페이로드를 검증합니다. 외부 LLM은 모의 응답을 사용합니다.

## 친구와 플레이 활동

- 팔로우를 없애고 프로필의 친구 요청·수락·거절·취소·삭제로 대체합니다. My와 채팅방 탭에서 친구를 관리합니다.
- 채팅방 탭의 기존 안내 문구 자리에 작은 프로필·접속 점·작품 활동을 표시합니다. 작품 탭에는 별도 친구 영역을 추가하지 않습니다.
- 활동이 3분 없으면 자리 비움으로 바뀌며 현재 작품은 유지합니다. 오프라인에서는 마지막으로 플레이한 작품을 보여줍니다. 여러 탭·기기는 최근 활동과 살아 있는 접속을 합쳐 판단합니다.
- 같은 접속에서 채팅방을 나왔을 때는 `접속 중 · 마지막 플레이 · 작품명`, 오프라인에서는 `오프라인 · 마지막 플레이 · 작품명`을 표시합니다. 새로 사이트에 들어오면 `접속 중`으로 시작하며, 브라우저 새로고침과 일시적인 연결 복구에서는 이번 접속의 기록을 유지합니다. 로그아웃·계정 변경은 새 접속으로 처리하며 전체 마지막 플레이 기록은 보존합니다.
- 새 작품 작성과 기존 작품의 편집 화면에서는 `작품명 제작 중`을 표시합니다. 편집을 마치면 `접속 중 · 마지막 제작 · 작품명`, 오프라인에서는 `오프라인 · 마지막 제작 · 작품명`으로 이어집니다. 제작과 플레이 중 최근 활동을 기록하며 공동 편집 권한도 확인합니다. 일반 화면에서 3분간 입력·클릭이 없으면 자리 비움으로 전환하고 작품 정보는 유지합니다.
- 일반 채팅방과 멀티챗 제목 옆에는 같은 작품을 플레이하는 친구만 표시합니다. 친구 사진을 누르면 프로필과 작품 활동을 볼 수 있습니다.
- 활동 공유는 친구 관리에서 끌 수 있습니다. 작품 제목·표지는 보는 회원의 기존 열람 권한으로 조회하며 다른 사람의 채팅방 ID·대화 내용은 공유하지 않습니다.
- 접속은 서버에 30초 간격으로 갱신합니다. 정상 종료·로그아웃은 해당 연결을 닫으며, 갑자기 끊긴 연결은 2분 후 만료합니다. 짧은 입력 이벤트마다 API나 DB 요청을 보내지 않습니다.
- 친구 상태 변경은 실시간으로 받아 갱신합니다. 구독마다 별도 채널을 사용해 친구 목록 로드·변경 시 이전 구독의 종료와 충돌하지 않습니다. 연결 오류는 자동 재연결하고 복구 즉시 최신 상태를 읽습니다. 알림이 빠져도 보이는 화면에서는 15초마다, 연결 장애 중에는 5초마다 보완 조회하며 탭 복귀 시 바로 동기화합니다.
- 서비스 이용은 회원 전용입니다. 비회원 앱 데이터 접근과 미사용 팔로우 테이블을 제거하되 로그인·회원가입에 필요한 등록 확인 RPC는 유지합니다. 기존 작품·채팅·플레이 통계 기록은 보존합니다.
- `node scripts/test-friends.mjs`는 친구 권한과 상태 전이, 접속 종료·늦은 요청, 여러 탭의 마지막 작품, 정확한 3분 경계와 오프라인 작품 보존을 검증합니다.
- `node scripts/test-friends-realtime.mjs`는 실제 SDK의 동일 채널 재사용·늦은 종료 경합, 연결 오류·시간 초과·종료 복구, 알림 누락·연속 수신, 탭 복귀와 계정 변경 정리를 검증합니다.

- 오프라인 친구는 서버가 마지막으로 연결을 확인한 시각을 기준으로 `방금 전/몇 분/몇 시간/며칠 전 접속`을 표시합니다. 기존 5초 화면 시계로 문구를 갱신하며 추가 조회는 하지 않습니다. 마지막 플레이·제작 작품은 함께 유지하고, 활동 비공개·대기 중인 친구에게 접속 시각은 제공하지 않습니다. 연결 기록 정리 뒤에도 마지막 접속 시각을 보존합니다.

### 멀티챗 혼자 진행

멀티챗 측면 메뉴의 페르소나 바로 아래에서 `함께 진행 / 나 혼자 진행`을 선택합니다. 방장과 참여자 모두 변경할 수 있습니다. 상대가 같은 방에 접속해 있거나 접속 상태가 확인되지 않으면 확인창을 표시합니다. 방의 진행 방식은 두 사람에게 공유되고, 동시에 변경한 요청은 버전 확인으로 덮어쓰기를 막습니다. 상대가 이미 제출한 입력은 버리지 않습니다.

혼자 진행은 지정된 PC의 입력 하나로 응답을 생성합니다. PC1·PC2 배정, 양쪽 페르소나와 유저 노트, 대화와 메모리는 유지됩니다. PC2 혼자 진행 시 입력도 `페르소나 이름(PC2): 내용` 그대로이며 빈 PC1 입력이나 자동 스킵을 추가하지 않습니다. 혼자 진행 중에는 진행자의 기기에 저장된 API 키를 사용하고, 함께 진행으로 돌아오면 저장된 공동 키 배분 규칙을 다시 사용합니다.

모델에는 현재 턴의 상태만 `Multichat Turn State` 메타데이터로 전달합니다. 프롬프트에서 `{{multichat_mode}}` (`solo` / `together`), `{{multichat_active_pc}}` (`PC1` / `PC2` / `PC1, PC2`)를 사용할 수 있습니다. 캐릭터의 대사·기억·행동에 관한 새 지침은 추가하지 않습니다. 생성이 시작된 턴의 상태는 고정되며 이후 설정 변경은 다음 턴에 적용됩니다. 재시도·리롤도 원래 턴의 진행 방식과 PC 식별자를 사용합니다.

`node scripts/test-multichat-solo.mjs`는 DB 권한·PC 고정·진행 전환·동시 변경·제출 충돌·키 배정·재시도·리롤·요약을, `node scripts/test-multichat-solo-ui.mjs`는 실제 설정 컴포넌트와 방 접속 훅의 확인·취소·중복 클릭·상태 충돌을 검증합니다. `test-multichat-shared.mjs`는 공통 프롬프트 조립기와 실제 HTTP 어댑터에서 두 PC의 단독 입력과 상태 전달도 검증합니다.

### 친구 플레이 시간

친구의 현재 작품과 마지막 플레이 작품에 이번 연속 플레이 시간을 표시합니다. 기존 30초 접속 확인과 5초 화면 시계를 재사용하며 초마다 DB에 쓰지 않습니다. 자리 비움(마지막 활동 후 3분)·채팅방 이탈·오프라인 때 멈추고, 같은 채팅방에 3분 이내 재입장하면 나가 있던 시간을 제외하고 이어갑니다. 3분이 지나 재입장하면 새 연속 플레이로 시작합니다. 같은 작품의 다른 채팅방은 별도로 계산하며, 같은 방을 여러 탭/기기에서 열어도 겹친 시간을 중복 계산하지 않습니다. 방에 머문 채 자리 비움인 동안에는 기록을 유지하고 활동 재개 시 이어갑니다. 제작·작품 수정에도 같은 규칙을 적용하되, 작품별 제작 시간과 채팅방별 플레이 시간은 따로 기록합니다.

시간은 서버의 활동 기록으로 계산하며 비공개 활동·수락 전 관계에는 노출하지 않습니다. 새로고침·재접속에서도 서버 기록을 이어받습니다. 기존 데이터의 과거 실제 플레이 시간은 소급 추정하지 않고 적용 이후 접속부터 기록합니다. 정상적인 방 이탈·종료는 즉시 멈추며, 갑작스러운 통신 단절은 기존 접속 유효기간(최대 2분)까지 연결 상태로 추정한 뒤 멈춥니다.

`node scripts/test-friend-play-time.mjs`는 실제 DB 범위 연산으로 정확한 자리 비움 경계·재개, 3분 재입장/초과 초기화, 방별 구분, 여러 기기의 구간 합집합, 오프라인 시간 제한과 연결 정리 후 보존, 실제 authenticated RPC·역할별 접근 및 UI 문구/시계 계산을 검증합니다.

제작 시간은 같은 작품의 편집 화면을 기준으로 기록합니다. 현재·자리 비움·오프라인 상태와 마지막 제작 작품에도 시간이 표시되며, 편집 화면을 나간 뒤 3분 이내 복귀하면 쉬었던 시간을 제외하고 이어갑니다. `node scripts/test-friend-creation-time.mjs`는 제작의 자리 비움·재개·3분 경계·작품별 구분·여러 편집 탭의 중복 제외, 플레이와의 분리, 공동 편집 권한 회수 및 활동 비공개를 검증합니다.

멀티챗 목록은 일반 채팅방처럼 썸네일·이름이 포함된 행을 누르면 열립니다. 참여자는 오른쪽 점 세 개에서 이름을 바꿀 수 있고, 방장에게는 기존 삭제 확인 메뉴도 표시합니다. 이름 변경은 방과 공통 세션 제목에 원자적으로 적용됩니다. 미참여자는 방을 열어 참가 화면을 확인할 수 있습니다. `node scripts/test-multichat-list-ui.mjs`는 실제 목록 JSX에서 행 이동·별도 메뉴·참여자 이름 변경·방장 삭제와 기존 일반챗 이름 변경을 검증합니다.
