## 표시와 전송 준비

소유 세션 확인 뒤 작품과 메시지 페이지가 준비되면 대화를 표시합니다. 프롬프트·페르소나·시작 설정·키워드·스토리 노트·계정 설정은 모두 성공해야 전송·재생성·편집·메모리 변경을 활성화합니다. 실패한 설정만 다시 불러오며 기존 대화와 입력은 유지합니다. 설정 실패 중에도 대화 TXT를 추출할 수 있습니다. 방·계정 이동이나 재시도 뒤에는 이전 결과를 적용하지 않습니다.

전송 직전 독립적인 대화 문맥과 테마 설정 조회도 동시에 시작합니다. 필수 문맥을 임의의 기본값으로 대체하지 않으며 유료 모델 요청은 자동 재시도하지 않습니다.

## 서버 적용

`supabase/migrations/20261024134703_atomic_chat_message_mutations.sql`과 `supabase/migrations/20261025012314_atomic_session_branch.sql`은 운영 프로젝트에 이미 적용했습니다. 파일의 함수 본문 MD5가 운영과 일치합니다. 함수 추가·교체이며 기존 대화·요약·설정 행을 일괄 수정하지 않습니다. 운영 데이터로 편집·삭제·분기 시험을 하지 않았습니다.

- `mutate_session_message`는 소유 세션을 먼저 잠그고 버전·기존 명령어를 검사합니다. 편집·삭제와 관련 요약 무효화를 함께 커밋하며 실패하면 모두 롤백합니다. 사용자 메시지·AI 답변·숨김 문맥을 처리하고 활성 답변 삭제 시 남은 리롤을 승격합니다. 명령어 제거 시 `command_prompt`도 제거합니다.
- 같은 변경의 재호출은 메모리를 반복 파괴하지 않습니다. 생성 중이거나 다른 화면에서 바뀐 메시지는 거부합니다. 연결 실패 뒤 변경 재전송은 최대 한 번이며 서버 상태도 읽지 못하면 입력을 유지합니다.
- `select_session_variant`는 이미 활성인 같은 답변을 오래된 기대 ID로 재선택해도 무변경 성공합니다. 다른 답변 선택의 충돌 보호는 유지합니다.
- `branch_session_at_message`는 방·메시지·유효한 요약·최신 노트를 함께 복사합니다. 설정 전체를 보존하고 캐시 기준을 새 메시지 ID로 변환합니다. 사용자 메시지에서 끝나면 아직 복사하지 않은 답변의 요약을 제외합니다. 같은 요청 ID는 중복 복사하지 않습니다.
- 세 함수 모두 SECURITY INVOKER·고정 search_path이며 기존 RLS와 소유자 검사를 따릅니다. 운영에서 익명 실행 불가·인증 사용자 실행 가능을 확인했습니다.

새 프런트엔드에 필요한 서버 함수를 먼저 적용했습니다. 구형 클라이언트와 호환되는 추가 변경이며 별도 수동 SQL은 필요 없습니다.
