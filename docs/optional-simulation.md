# Optional dice and character knowledge

Both features default to OFF and can be enabled independently in Session menu → Conversation → 주사위 · 정보 관리. This also applies to multichat; auxiliary calls use the existing generation owner's OpenRouter key. No API key is stored in simulation records.

The original `assemblePrompt`, history selection, main OpenRouter adapter, response commits, summaries and reroll direction handling remain the baseline. A guarded call extends only enabled requests. Disabling both adds no simulation prompt, state query or auxiliary model call to generation. The separate, requested theme parsing improvement remains active independently of these switches.

## Controls

- Settings → Administrator → 주사위 · 정보 관리: two editable global prompts, analysis model and Decisions verification model. Saves use administrator authorization and compare-and-swap to protect drafts from concurrent writes.
- Work editor → 판정·정보: work-specific dice/information text and numeric dice rules. This section has its own save button and browser draft. It does not overwrite the existing work editor transaction or main prompt.
- Session menu: independent switches, first recording point, reroll policy, information table, evidence/knowledge correction, recent rolls and separate auxiliary usage totals.
- Existing sessions start information tracking from the latest scene when first enabled. Choosing “처음부터” additionally processes the active history in order. Long initialization costs more and can be resumed after interruption. Advancing the starting point after recording is prohibited to avoid silently losing established knowledge.

## Runtime

With dice enabled, a schema-constrained cheap model selects up to four PC actions, actor/target/skill and a bounded situational modifier. Code applies the work's ability difference and freezes success/critical thresholds before an authenticated database function rolls uniformly using rejection sampling over `extensions.gen_random_bytes`. Unspecified numeric abilities are explicitly treated as zero. Criticals disabled using `die + 1` stay disabled under advantage.

The default is d6, success at 5, critical at 6. Those are defaults, not a universal TRPG ruleset. Developers can edit die size, thresholds, skills, character stats and the conversion interval. No arbitrary formula execution is supported.

Retries and ordinary rerolls reuse the same result. A fingerprint includes input, recent context, applicable rules and retrieved facts so an edited action/context cannot inherit an unrelated roll. The session can opt into rerolling the dice; a nonempty reroll direction also reanalyzes the attempt. Rolls are never generated by the language model. Newly invented NPC actions during the streamed narrative are not independently rolled by this first version.

With information management enabled, confirmed responses produce bounded structured deltas. Atomic facts are separate from character knowledge. An exact evidence substring must exist before a proposed O reaches Jev; uncertain or rejected O candidates stay unconfirmed. Suspicions and beliefs are separate from knowledge. A failed verification does not become an invented explanation. The verifier's 0.9 cutoff is a conservative initial engineering default, not a measured 90% accuracy guarantee.

The projection keeps registered characters after death, hostility or departure. Each main request receives relevant facts and knowers, not the entire table or every historical reason. Secrets relevant to the current cast are retained preferentially; oversized mandatory context raises an explicit budget error instead of silently discarding it. The table paginates large fact sets.

The main model can still see secrets present in the original work prompt. This feature improves narrative consistency; it is not a strict secrecy boundary, and cannot retract a secret already streamed to the user. Author-secret isolation and a buffered pre-display check are separate extensions.

## Persistence and concurrency

The additive migration `20261030074004_optional_simulation.sql` creates work settings, response deltas, rolls, auxiliary usage and a private processing lease. It adds only opt-in settings/defaults to existing session/platform tables. It does not update stored messages, existing prompts, history or usage totals.

Message IDs, content versions and the active transcript prefix identify each accepted delta. Editing, deleting or selecting a different variant invalidates derived state after the changed point. A manual knowledge correction uses compare-and-swap and invalidates later deltas. Rebuilding state does not automatically rewrite already-existing downstream narrative.

A renewable, expiring cross-tab lease serializes extraction and prevents duplicate paid processing after the main response commits. Manual corrections and toggle changes wait until generation/processing completes. Stale writes are rejected. The next enabled generation repairs missing deltas before continuing.

“Background” means asynchronous work in the current browser lifecycle. Closing the app may interrupt it; source messages and missing-delta detection allow resumption. This version does not persist API keys or claim to run indefinitely after the browser closes. Auxiliary costs remain separate from legacy message/session main-model totals and are visible in the new panel.

## Tags

`{{theme::...}}` and `{{sync_date::...}}` work at the beginning, middle or end, in either order. The theme selector walks candidates backwards and chooses the last valid authorized theme; `keep` is an explicit keep instruction. The observation fingerprint includes all theme directives, so editing a valid earlier tag still works when a later invalid tag remains unchanged. Ordinary body edits do not replay an unchanged directive.

Date propagation already searches globally on the server and uses the last valid date in the latest active completed response. Its existing edit/delete/variant and unlink cleanup behavior is retained. User messages, interrupted responses and incomplete streamed tags do not execute metadata changes. Existing rendering strips both tag types wherever they occur.

## Verification

`npm test` includes `npm run test:simulation`. The feature tests exercise actual HTTP serialization with mocked paid APIs, real JSX handlers and real Postgres functions/RLS through PGlite. The OFF test compares 18 generated request bodies against a synthetic fixture recorded from pre-feature commit `26eb265`, for legacy sessions and explicit OFF settings. It requires no old Git history in CI.

Coverage includes independent controls/prompts, cached-prefix placement, dice range boundaries/rejection sampling/idempotency, source revisions, stale/manual writes, processing leases, member/owner/admin authorization, missing evidence, uncertain verification, per-role cost recording, position-independent mixed tags and the existing send/reroll/summary/cache regressions.

No real paid model evaluation is included in the automated suite. Generation quality, latency and the verifier threshold must be evaluated on actual Korean roleplay sessions. No token or response-time guarantee is implied by the previous planning estimates.
