# 채팅 안정성 및 조회 최적화

이 변경은 채팅방 전환, 리롤·요약·복제의 부분 저장, 개인 설정 공개 조회를 수정하고 전송 문맥과 카탈로그에서 불필요한 본문 전송을 줄입니다.

## 적용

기존 마이그레이션이 적용된 DB에서 `supabase/migrations/20261022094256_integrity_and_query_safety.sql`을 먼저 실행한 뒤 이 코드를 배포합니다. 운영 DB에는 이 작업에서 적용하지 않았습니다. 새 코드는 해당 파일의 RPC를 사용하므로 코드만 먼저 배포하면 채팅을 불러오지 못합니다. SQL 적용 직후의 구형 클라이언트는 다른 사람의 작성자 이름을 불러오지 못할 수 있으므로 코드 배포와 클라이언트 새로고침까지 함께 진행합니다.

`0032_message_turn_idempotency.sql`을 대신 실행하지 않습니다. 새 마이그레이션은 기존 메시지의 ID·본문·턴 번호·활성 선택·캐시 참조를 삭제하거나 바꾸지 않습니다. 이미 충돌한 기존 행에는 `legacy_turn_conflict`를 표시해 보존하며, 새 행 사이의 같은 사용자 턴·AI 리롤 번호 중복은 고유 인덱스로 차단합니다. 역사적 충돌 행을 자동으로 선택·삭제·재번호화하지 않습니다. 브라우저 역할은 이 보존 표시를 위조하거나 해제할 수 없습니다.

마이그레이션은 기존 두 고유 인덱스가 있으면 유지하며, 재실행해도 메시지 원문과 설정을 초기화하지 않습니다. 공개 프로필 미러는 반복 갱신할 수 있고 나머지 DDL과 함수도 재실행을 처리합니다.

## 접근 제어

- `profiles` 전체 읽기는 계정 소유자로 제한합니다. 공개 이름·소개·아바타는 `public_profiles`의 네 필드만 조회합니다. 비공개 스키마의 고정 search_path 트리거가 공개 필드를 동기화하며 클라이언트의 직접 쓰기는 허용하지 않습니다.
- 멀티챗 생성 함수는 비로그인과 존재하지 않는 방을 명시적으로 거부하고 NULL에도 안전하게 방장·상태를 검사합니다. 익명/PUBLIC 실행 권한을 회수합니다.
- 새 세션 RPC는 SECURITY INVOKER로 기존 RLS를 따르고, 소유한 세션을 잠근 뒤 관련 변경을 하나의 트랜잭션으로 처리합니다.
- 새 비공개 작품의 INSERT RETURNING에서 소유자를 직접 확인하도록 읽기 정책을 보강합니다. 공동 편집자와 공개·일부 공개 작품의 기존 접근도 유지합니다.

## 저장과 화면

- 리롤 초안은 비활성 상태로 저장하고 확정할 때 이전 답변과 원자적으로 교체합니다. 오래된 선택으로 다른 화면의 선택을 덮어쓰면 오류를 반환합니다. 이미 요약된 답변을 교체하면 해당 답변 이후 요약의 활성 상태를 해제하고 이전 체크포인트를 적용합니다. 노트 원문은 삭제하지 않으며, 같은 답변을 다시 선택하면 메모리를 유지합니다.
- 최종 응답·리롤 선택·토큰/비용 증가는 한 번에 커밋합니다. 동일 응답의 사용량을 다시 합산하지 않습니다. 최종 저장 응답이 소실되면 완료 행을 다시 확인하며, 실패 처리도 streaming 행만 갱신해 완료된 답변을 중단 상태로 되돌리지 않습니다.
- 생성 요약은 원본 메시지의 버전과 기존 요약을 검사한 후 버전·메시지 표시·세션 메모리·사용량을 함께 저장합니다. 통합 생성은 선택한 노트 중 마지막 기준 턴을 사용하고, 생성 중 노트 원문이나 기준 턴이 바뀌면 저장을 거부합니다. 수동 편집·선택·삭제도 원자적으로 처리하고 비활성 노트 편집·삭제는 현재 메모리에 영향을 주지 않습니다. 로컬의 일반 생성과 요약 생성은 동시에 시작하지 않습니다.
- 작품 복제와 시작 채팅방 생성은 하위 설정·메시지까지 함께 성공해야 커밋됩니다. 복제본은 비공개로 만들고 공용 테마의 팔레트·AI 조건·시간 옵션과 기본 테마 연결을 복사합니다. 개인 테마는 복제하지 않습니다.
- 계정이 바뀌면 쿼리 캐시와 화면 상태를 분리하고 진행 중 모델 요청을 중단합니다. 취소는 화면 수명과 별도로 관리하여 채팅을 떠난 뒤 로그아웃해도 동작하며, 문맥 조회 단계부터 등록합니다. 같은 계정에서 화면만 이동하면 진행 중 요청은 유지합니다. 채팅 경로도 방별로 상태를 분리해 이전 페르소나·시작 설정이나 늦게 도착한 응답이 다른 방 화면을 덮지 않게 합니다.
- 키워드 활성화에서 현재 입력을 한 번만 계산합니다. 하트 저장은 성공 후 캐시를 갱신하고 실패를 표시합니다.

## 조회 및 저장량

- 화면은 논리 턴 커서를 사용합니다. 같은 created_at의 과거 복사 기록이나 1,000행 API 제한으로 메시지가 누락되지 않도록 페이지를 JSON으로 반환합니다.
- 전송은 하나의 `session_generation_context` 호출로 읽습니다. 요약 이전 기록·비활성 리롤은 순서와 버전 메타데이터만 받고, 필요한 대화·숨김 시작 문맥·키워드용 입력은 원문을 받습니다. 요약 경계는 DB의 현재 요약을 기준으로 하며 수동/자동 캐시 계산은 기존 전송용 기록에 적용합니다. 리롤은 필요한 원문을 다시 읽고 내보내기·분기·전체 요약의 전체 기록 접근도 유지합니다.
- 임시 저장은 기본 1초 간격이며 동시 쓰기는 하나만 수행합니다. 대기 중 스냅샷은 최신 본문으로 합치고 최종·중단 본문이 이전 임시 쓰기로 덮이지 않게 합니다. 강제 종료 시 저장되지 않을 수 있는 최근 구간이 기존 500ms보다 길어지는 절충이 있습니다.
- 플러그인·명령어 카탈로그는 메타데이터만 조회하고 본문은 선택·미리보기·수정·복사 시 읽습니다. 길이·개수 제한을 추가하지 않으며 검색과 지속 세션 프롬프트는 유지합니다.

## 검증

Node 22.23.4에서 `npm run typecheck`, 전체 `npm test` 15개 스크립트와 `npm run build`를 실행합니다.

추가 DB 테스트는 실제 기존 마이그레이션으로 스키마를 만들고 이 SQL을 PGlite에서 실행합니다. Storage·가입 비밀번호 서비스 초기화와 기존 삭제 복구 SQL만 제외합니다. 원문·ID 보존, 재적용, 익명/타인 접근 차단, 공개 프로필 동기화, 신규 중복 거부, 리롤 선택/최종 통계/요약 INSERT/작품 하위 INSERT 실패의 롤백, 중복 사용량 합산 방지, 원본 변경 감지와 팔레트 보존을 검증합니다.

같은 시각의 합성 메시지 1,200개를 120페이지로 빠짐없이 읽었습니다. 500턴까지 요약한 합성 대화의 전송용 JSON은 전체 원문 조회의 40% 미만이며, 이는 테스트 데이터의 전송량 비교입니다. 운영 속도 향상률을 측정한 결과는 아닙니다. 임시 저장 테스트는 첫 쓰기가 지연된 동안 들어온 100개 갱신이 최신 스냅샷 하나로 합쳐지는 것을 확인합니다.

Chromium에서 모의 Supabase/OpenRouter로 실제 UI의 전송, 저장 성공 응답 소실 복구, 리롤·선택 실패/성공, 방 전환 후 페르소나 분리, 목록의 본문 제외와 상세 지연 조회, 모바일 폭과 레거시 화면을 확인합니다. 실제 사용자 계정이나 유료 모델 요청은 사용하지 않습니다. 운영 PostgREST 종단 검증과 실기기 검증은 별도입니다.

| --- | --- | --- |
| 긴 방에서 요약 통합 시 화면에 보이는 5턴으로 기준이 축소됨 | 선택 노트의 마지막 기준 턴과 전체 대화 범위를 사용 | 30턴 방에서 10·20턴 노트 통합 시 20 유지 |

| 요약된 답변을 리롤로 교체해도 메모리가 이전 답변을 참조함 | 답변 선택과 유효한 요약 체크포인트 복귀를 함께 저장 | 새 요약이 생성 도중 먼저 커밋되는 경우, 비용 저장 실패 롤백, 같은 답변 재선택 검증 |

실제 DB에서 읽은 전체 기록과 최적화된 문맥을 실제 프롬프트·캐시 조립기에 넣어 요약 경계 5개 × 일반/리롤 × 캐시 4모드, 40가지 전송 메시지 JSON이 일치하는지 비교합니다. 숨김 시작 문맥, 비활성 리롤, 현재 DB 요약, 키워드, 페르소나, 플러그인과 테마 태그를 포함합니다. 기존 작품 결합 미사용 15개 전체 요청 바이트 비교도 함께 유지합니다.

Supabase CLI `db advisors --local --type all`도 시도했으나 로컬 Postgres 54322가 없어 연결되지 않았습니다. 새 SQL의 RLS와 트랜잭션 검증은 PGlite로 수행했습니다.

툴체인 메이저 업데이트, PWA 선행 캐시 범위 변경, 멀티챗 Realtime 이벤트별 부분 갱신은 이 변경에 섞지 않았습니다. 기존 레거시·개선 UI, 두 450px 기본값, 테마 처리, TXT 형식과 작품 결합 미사용 요청의 동등성은 기존 회귀 검증을 유지합니다.
