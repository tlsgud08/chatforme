# 검색·로딩·스크롤 회귀 수정

## 확인한 원인과 변경

| 증상 | 확인한 원인 | 변경 |
| --- | --- | --- |
| 결합할 일본어 제목이 검색되지 않음 | 제목의 문자 인코딩은 정상이지만 관리자에게도 다른 제작자의 `unlisted` 작품을 제외하는 필터가 적용됨 | 관리자 검색에서는 해당 필터를 생략. 일반 사용자 검색 규칙, RLS, 검색 특수문자 이스케이프 유지 |
| 배포 뒤 열린 탭에서 채팅·작품 화면 로딩 실패 | `React.lazy`로 화면을 나눈 상태에서 새 서비스워커의 `skipWaiting()`이 즉시 활성화되고 Workbox가 이전 화면 파일을 삭제함 | 새 워커는 기존 탭이 닫힐 때까지 대기. 기존 워커와 이전 화면 파일 유지 |
| 로딩 중 화면 전체가 사라짐 | `Suspense`와 오류 경계가 전체 프레임을 감쌈 | 각 경로의 본문만 감싸서 사이드바·기존 UI의 하단 탭 유지. 오류는 콘솔에도 기록 |
| 채팅방 목록 표시 지연 | 방 목록 조회 뒤 대화 수 RPC를 기다려야 목록을 반환함. RPC의 모든 실패를 방 개수만큼의 추가 조회로 확장함 | 방 목록과 집계를 별도 쿼리로 분리. 스키마에 RPC가 없을 때만 최대 4개씩 호환 조회. 집계 실패를 0회 또는 빈 목록으로 표시하지 않음 |
| 화면 이동 때 반복 조회 | 사이드바에서 경로마다 `refetch()`를 호출하여 30초 캐시를 무시함 | 진행 중 요청과 유효한 캐시 공유. 새 방 생성·분기·응답 저장·이름 변경·보관·삭제 시 무효화 유지 |
| 작품 상세 화면의 불필요한 전송량 | 상세 소개에서도 사용하지 않는 작품 프롬프트를 함께 조회함 | 소개에 필요한 메타데이터만 조회. 실제 채팅의 프롬프트 조회는 유지 |
| 생성·편집 뒤 강제 스크롤 | `[messages, sending]` 변경마다 하단으로 이동하는 예약 콜백, 편집창의 자동 포커스 | 처음 방을 열 때만 최신 대화로 이동. 이후 보이는 메시지와 화면 내 위치를 보존. 편집 포커스는 `preventScroll` 적용 |
| 백그라운드 새로고침 때 과거 대화가 사라짐 | 최신 페이지를 읽을 때 이미 펼친 이전 대화까지 교체함 | 새 페이지보다 오래된 대화를 유지하고 최신 구간만 교체 |

## 검증

Node 22에서 `npm run typecheck`, `npm test`, `npm run build`를 실행합니다. `npm test`에는 집계 실패 시 추가 요청 방지, 이전 스키마 호환 조회의 동시성 제한, 취소, 생성·편집·이전 페이지 추가에 따른 독립 스크롤 검증이 포함됩니다. 기존 페이로드·테마·결합·분기·RLS 테스트도 유지합니다.

실제 브라우저 회귀 시험은 다음과 같이 실행합니다.

```sh
npx playwright install chromium
npm run test:browser:loading
```

별도 Chromium이 준비된 환경에서는 `PLAYWRIGHT_EXECUTABLE_PATH`를 지정할 수 있습니다. 시험은 임시 디렉터리에 서로 다른 두 프로덕션 빌드를 만들고, 한 탭을 연 채 서버의 버전을 교체합니다. Supabase·모델 호출은 모두 모의 응답으로 처리하며 운영 데이터나 유료 모델을 사용하지 않습니다.

- 기존 코드: 워커가 즉시 활성화되고 이전 채팅 파일의 404 뒤 오류 화면 재현.
- 수정 코드: 워커가 대기하고 이전 파일을 사용하여 정상 진입.
- 집계 응답을 의도적으로 2초 지연한 조건에서 기존 목록은 약 2.34초 후, 수정 목록은 약 0.07–0.10초 후 표시. 운영 환경의 속도 측정값은 아님.
- 하단 근처에서 편집한 전후 스크롤 `6424 → 6424`, 위를 읽으며 응답을 생성한 전후 `200 → 200` 확인.
- 관리자 세션 메뉴의 일본어 검색, 모바일 너비의 기존 UI, 집계 503 실패 중 목록 유지, 화면 파일 실패 후 탭으로 복귀, 상세 메타데이터 조회 검증.

## 적용

추가 SQL이나 운영 데이터 변경은 없습니다. 배포 이후 새 워커는 이전 버전을 사용 중인 모든 탭이 닫히면 활성화됩니다. 작성 중인 내용을 저장하고 앱의 기존 탭을 모두 닫은 뒤 다시 열면 새 버전을 사용할 수 있습니다. 화면 분할 로딩과 이미지 캐시는 계속 사용합니다.
