# 작품 결합

세션 메뉴의 채팅 탭에서 플러그인 바로 아래에 있습니다. 채팅방별로 기능을 켜고 여러 작품을 검색해 추가할 수 있습니다. 메인 작품은 최우선으로 고정되며, 추가 작품의 위아래 버튼으로 적용 순서를 바꿉니다. 끄면 선택 목록은 보관합니다. 일반 채팅의 전송과 다시 생성에 적용되며, 채팅방 분기 시 설정도 복사합니다.

## 적용 순서와 기존 요청 보존

작품 결합을 끄거나 추가 작품이 없으면 기존 프롬프트 조립 경로를 그대로 사용합니다. 추가 헤더, 지침, 빈 필드를 OpenRouter 요청에 넣지 않습니다. 변경 전 커밋 `3e4b255`에서 캡처한 실제 직렬화 요청 본문을 `scripts/fixtures/work-combination-disabled.json`에 보관하고, 다섯 가지 문맥에 대해 미설정·비활성·빈 목록의 15가지 경우를 바이트 단위로 비교합니다.

결합을 사용하면 기존 `systemParts.core`의 작품 프롬프트 위치만 다음과 같이 확장합니다.

1. 관리자 설정에 저장된 작품 결합 지침
2. 메인 작품 이름, 최우선 표시, 원래 메인 프롬프트
3. 추가 작품 이름, 1부터 시작하는 우선순위, 각 메인 프롬프트

이후 테마 지침, 페르소나, 유저 노트, 플러그인, 요약, 키워드북, 대화 기록은 기존 처리와 순서를 유지합니다. 추가 작품에서는 `main_prompt`와 사용 가능한 작품 테마를 가져옵니다. 해당 작품의 키워드북, 시작 설정, 명령어는 가져오지 않습니다. 모델, 샘플링, 추론, 출력량, 캐시 설정을 변경하지 않습니다. 프롬프트 변경에 따른 캐시 적중률은 달라질 수 있습니다.

## 결합 작품 테마

결합을 켜고 추가 작품이 있으면 메인 작품과 모든 추가 작품의 공용 테마 및 본인의 작품 전용 테마를 채팅방에서 사용할 수 있습니다. 테마는 원래 작품에 그대로 두고 참조하며, 다른 사용자의 비공개 테마나 결합 밖 작품의 테마는 포함하지 않습니다. 작품 테마 선택 화면은 메인 → 추가 우선순위 순으로 묶고 작품명을 표시합니다. 우선순위가 낮아도 테마를 제외하지 않습니다. 새 개인 작품 테마는 메인 작품에 만들고, 기존 개인 테마를 편집할 때는 원래 소속을 유지합니다.

유동적 모드에서만 전체 결합 테마 목록과 적용 조건을 AI에 전달합니다. 결합 모드의 목록 `이름`에는 `id:테마UUID`를 쓰고 별도로 테마명과 작품명을 표시합니다. 낮·밤 대상은 `id:테마UUID:낮` / `id:테마UUID:밤`으로 나눕니다. 따라서 작품명이나 테마명이 같아도 모든 후보를 각각 선택할 수 있고, 이름·우선순위가 바뀌어도 ID는 유지됩니다. 기존 이름 태그는 현재 목록에서 유일한 경우만 해석합니다. 수동 고정 모드, 단일 팔레트, 낮·밤 전용 조건과 전환 제외 옵션은 기존 규칙을 유지합니다.

전송 직전에 결합 설정·작품 접근 권한·테마 목록을 확인합니다. 테마 조회 실패도 사용자 메시지 저장과 모델 호출 전에 중단하고 입력을 복원합니다. 응답 적용 시 현재 목록을 다시 확인하고 저장 조건에 결합 설정을 포함하므로, 다른 기기에서 제외한 작품의 테마를 늦게 도착한 응답이 다시 적용하지 않습니다. 목록이 길면 작품 ID를 50개씩 나누고 테마를 500행씩 조회합니다. 전송 시 작품명은 이미 읽은 결합 작품 정보에서 재사용합니다.

결합을 끄거나 작품을 제외할 때 그 작품의 테마가 적용 중이면, 같은 DB 변경 안에서 테마 참조와 낮·밤 상태를 지우고 유동적 모드로 복귀합니다. 화면은 기존 계정 선호에 따라 메인 작품 기본 테마, 그다음 계정 테마를 사용합니다. 메인 작품이나 전역 테마를 고정해 둔 경우는 유지합니다. 테마 ID를 새로 지정할 때는 DB도 활성 결합 범위와 접근 권한을 검증합니다. 삭제·권한 회수 이후에도 결합 해제가 가능하며, 분기에는 결합 설정과 사용 중인 테마를 함께 보존합니다.

결합을 끄거나 추가 작품이 없으면 기존 이름 기반 테마 목록을 그대로 사용하며, 원래의 직렬화 요청 본문을 보존합니다.

## 관리자 지침

설정 → 운영자 → **관리자 — 작품 결합 지침**에서 편집하고 전용 저장 버튼으로 저장합니다. 기존 전역·테마·멀티챗 프롬프트 저장과 독립적으로 처리합니다. 빈 문자열을 저장하면 별도 기본값으로 대체하지 않고 지침 문구를 생략합니다. 작품 이름과 우선순위 표시는 계속 포함됩니다.

## 데이터와 오류 처리

- `sessions.work_combination_enabled`: 기본값 `false`.
- `sessions.combined_work_ids`: 우선순위 순서의 UUID 배열, 기본값 빈 배열. 프롬프트 본문을 세션에 복제하지 않습니다.
- `platform_config.work_combination_prompt`: 관리자가 편집할 공통 지침.

검색에서는 공개 작품과 RLS로 허용된 비공개 작품, 본인의 일부 공개 작품을 찾을 수 있습니다. 검색 결과에는 프롬프트 본문을 요청하지 않습니다. 결합 요청 직전에 저장된 선택 순서와 추가 작품의 현재 프롬프트·관리자 지침을 읽습니다. 삭제·권한 회수·빈 프롬프트·조회 실패는 사용자 메시지 저장 및 모델 호출 전에 중단하고 입력을 복원합니다. 접근 불가 작품이 있어도 결합을 끌 수 있습니다.

저장은 기존 활성 상태와 작품 목록을 함께 비교하므로 다른 화면의 변경을 조용히 덮어쓰지 않습니다. 충돌 시 설정 새로고침 버튼으로 현재 값을 읽을 수 있습니다. 저장 중에는 추가 저장과 채팅 전송·분기를 막으며, 화면을 닫아도 진행 중인 저장의 잠금은 완료까지 유지합니다. 검색어 변경·화면 닫기에 따른 이전 검색 요청은 취소합니다.

## DB 적용

브랜치 코드를 사용할 DB에 `supabase/migrations/20261022031523_session_work_combination.sql`을 먼저 적용합니다. 기존 데이터나 설정된 지침을 덮어쓰지 않으며, 기존 채팅방은 비활성 상태로 시작합니다. 이 브랜치 작업에서는 운영 DB를 변경하지 않습니다.

결합 작품 테마를 사용하려면 이어서 `supabase/migrations/20261022233349_combined_work_themes.sql`을 코드 배포 전에 적용합니다. 기존 `optional_day_night_variants`까지의 테마 마이그레이션이 전제입니다. 새 컬럼·테이블·테마 복사는 없으며 테마 참조와 낮·밤 검증 트리거만 확장합니다. 설치·재실행 시 저장된 설정과 팔레트를 변경하지 않습니다.

추가 컬럼은 기존 세션 소유자 RLS 및 관리자 설정 RLS를 사용합니다. 검증 트리거는 SECURITY INVOKER로 실행해 작품 RLS를 우회하지 않습니다. 중복·메인 재추가·잘못된 배열 구조·접근 불가 작품 활성화를 DB에서도 거부합니다. 관련 필드 변경에만 트리거를 실행하므로 권한이 바뀐 뒤에도 기존 노트나 토큰 통계 업데이트를 막지 않습니다.

## 검증

Node 22에서 `npm run typecheck`, `npm test`, `npm run build`를 실행합니다. 테스트에는 기존 요청 보존, 프롬프트 순서와 원문, 최신 지침 조회, 검색 특수문자, 다수 작품 조회 분할, 동시 저장 감지, PGlite에서의 실제 트리거·RLS·관리자 지침·마이그레이션 재실행 검증이 포함됩니다.

`test-combined-work-themes.mjs`는 동명 테마 전체 선택, ID·이름 태그, 단독 작품 호환, 1,000행 초과 조회, 취소·실패와 권한 상실을 검증합니다. `test-combined-work-themes-db.mjs`는 실제 테마 마이그레이션과 작품/세션 RLS를 함께 적용해 공유 범위, 활성 결합 제한, 수동·유동적·낮밤·단일 테마, 분기, 제외·해제 원자성, 삭제 복구 및 재실행 보존을 검증합니다.
